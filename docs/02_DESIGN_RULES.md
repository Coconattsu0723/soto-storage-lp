# soto Design Rules

## 0. 文書の役割

LP全体のデザイン判断を統一する正本。正式決定、方向性、実装時に調整する候補値を区別して記録する。

## 1. デザインコンセプト

**暮らしの余白を感じる、静かで親しみのある収納ブランド。**

### 基本方針

- 写真を主役にする。
- 情報はシンプルに整理する。
- 信頼感は派手な装飾ではなく、静かなレイアウト、十分な余白、明快な情報階層で表現する。
- キャラクターイラストは親しみを加える補助要素として使う。
- 参考サイトの固有レイアウト、コピー、色、素材は模倣しない。

### ビジュアル比率の目安

**Lifestyle 70 / Information 20 / Character 10**

厳密な面積比ではなく、写真中心のブランド世界を崩さないための判断基準とする。

## 2. カラーパレット

|---|---|---|---|
| Base | Warm Ivory | `#FFF9F2` | ページの基本背景 |
| Sub Background | Oat Beige | `#F4E8DA` | セクション切替、カード背景 |
| Main Text | Cocoa Brown | `#4A382F` | 見出し、本文、ロゴに近い主要色 |
| Sub Text | Taupe Brown | `#7A665B` | 補足、ラベル、二次情報 |

| Light Accent | Butter Cream | `#F3D58D` | 小さな強調、イラスト補助 |

| CTA Hover Candidate | — | `#B9694E` | 主CTA hover候補。実装時にコントラストと状態差を確認 |

### 色の運用ルール

- ページ背景はWarm Ivoryを中心にする。
- セクション切替にはOat Beigeを使う。
- 見出し・本文はCocoa Brownを基本とし、補足はTaupe Brownを使う。
- 主CTAはSoft Terracottaを中心にする。
- Apricot / Butter Creamは小面積のアクセントに限定する。
- 青はブランドカラーとして使わず、キャラクター内の差し色程度に限定する。
- 色だけで状態や意味を伝えない。
- 本文、リンク、ボタン、フォーム各状態は実装時にコントラストを測定する。

## 3. Typography

### Font Family

- 日本語：**Noto Sans JP**
- 英字：**Inter**
- ロゴ：正式採用済みの小文字`soto`ワードマーク画像を使用する。

### 文字設計

- HeroコピーはSPで2〜3行になっても意味とリズムが保たれるサイズにする。
- 見出しを過度に太くしない。
- 行間と余白で静かさと上品さを出す。
- 英字ラベル + 日本語見出しの2階層を基本候補とする。
- 強調は太字だけに頼らず、サイズ、余白、配置の差で表現する。
- 本文は長い1行を避け、読みやすい行長を保つ。
- 具体的なfont-size、line-height、letter-spacing、weightの段階は実装時に全幅で検証して確定する。

## 4. Shape / UI

### Border Radius

現時点の候補：

- Small：8px
- Medium：12px
- Large：20px

候補値であり、カード、画像、ボタンへ一律に適用しない。用途別の段階とブランドの静かな印象を保てるかを実装時に検証する。

### Border

- 基本候補：`1px solid #DED0C3`
- 情報整理に必要な箇所だけに使い、囲みを増やしすぎない。

### Shadow

- 原則なし。
- 浮き上がりが操作理解に必要な場合のみ、極めて控えめに使う。
- カードを影で大量に分割しない。

## 5. Spacing

- 「暮らしの余白」という価値を、セクション間・見出し周辺・写真周辺の余白で表現する。
- SPでは余白を削って情報を詰め込まず、1つずつ理解できる縦のリズムを優先する。
- PCではコンテンツ幅を無制限に広げず、外側の余白をブランド表現として残す。
- 余白値は一貫したスケールへ整理するが、具体値は実装時に375pxから検証して確定する。
- テキスト内余白、コンポーネント内余白、コンポーネント間、セクション間の4段階を混同しない。

## 6. Container

- SPは画面端に十分な安全余白を確保した1カラムを基本とする。
- 768px付近では内容に応じて2カラムへ切り替える。
- 1024px以上でも写真・文章の行長が広がりすぎない最大幅を設定する。
- フルブリード写真を使用する場合も、本文の読み位置は共通コンテナへそろえる。
- コンテナ最大幅と左右余白の数値は未確定。実装時に1366px / 1440pxを含めて確定する。

## 7. CTAデザイン

- 主CTAはSoft Terracottaの塗りボタンを基本とする。
- 副CTAが必要な場合は枠ボタンを使い、主従を明確にする。
- 大きすぎる販促表現、点滅、過剰な影、強い煽りを使わない。
- 押した後の行動が分かる正式文言を使用する。
- hoverだけでなく、focus-visible、active、disabledの状態を区別する。
- SPで十分なタップ領域とボタン間隔を確保する。
- テキストと背景のコントラストは実装時に確認する。

## 8. 写真トーン

### 共通ルール

- 都市部の1LDK〜2LDK程度のマンション。
- 30代前後の共働き夫婦の暮らしを想定する。
- 自然光、暖かく柔らかい光。
- アイボリー、ベージュ、グレージュ中心。
- 木、布、植物など自然な生活素材を含める。
- 彩度を上げすぎず、明るすぎる広告写真にしない。
- 清潔さを保ちながら自然な生活感を残す。
- モデルルームのように完璧すぎる空間、AI生成感の強い過度な美しさを避ける。
- 写真内へ文字やロゴを入れない。

### 人物

- 日本人30代前後の男女を想定する。
- 自然な生活の一場面として写す。
- カメラ目線を基本にしない。
- 不自然な笑顔を避ける。
- 白、アイボリー、ベージュ、グレー、ネイビー等の落ち着いた服装を基本とする。

### 避ける表現

- 巨大倉庫が主役の写真
- 段ボールだらけの空間
- 汚部屋表現
- 空っぽすぎるミニマル空間
- 海外ストックフォト感
- CGI / 3DCG感の強い空間

## 9. 写真シリーズの連続性

Hero / Before / Afterは、**同じ住まい・同じブランド世界**に見えることを正式ルールとする。

### Before

- Heroと同じ部屋・リビング構成。
- 棚はあってよい。
- スーツケース、季節家電、収納ケース、ブランケット等で少し圧迫感を表現する。
- 汚部屋にはしない。

### After

- Heroと同じ部屋・リビング構成。
- Heroにない大型クローゼットを置かない。
- 不要な大型棚を増やさない。
- 収納ケース、季節家電、スーツケース等を撤去する。
- 床と壁際の余白を明確に見せる。
- モデルルームほど空にしない。

## 10. キャラクターイラスト

### Character Master

**Brand Philosophy Character**を正式なCharacter Masterとする。

以下を全キャラクターで統一する。

- 顔
- 正式採用1案目の口元
- 目
- ほっぺ
- 耳
- 頭身
- 手足
- 色
- 塗り
- 手描き感

### スタイル

- シンプルで手描き感がある。
- ゆるいフォルム、少ない描き込み、小さな表情。
- 柔らかい赤・黄色などの暖色を中心に、一部ブルーを差し色として使える。
- 子ども向けになりすぎない。
- 背景透過を基本とする。

### 使用ルール

- 説明、共感、UIの補助として使用する。
- Heroの主役にはしない。
- Storage & SecurityとPriceではキャラクターを主に使わない。
- 正式採用済み6点以外を勝手に追加しない。

## 11. アイコン

### What You Can Store

- 正式カテゴリー：SEASON / TRAVEL / HOBBY / HOME。
- 同じ線、塗り、色数、視覚サイズで統一する。
- ラベルと組み合わせ、アイコンだけに意味を依存しない。

### Storage & Security

- 正式採用済みの4点を使用する。
- 意味を保ちながら情報量を抑える。
- Security Icon 02は、スマートフォン + BOX + チェックを中心にしたシンプル案を使用する。
- 小さい表示でも主題が判別できるようにする。

### 共通ルール

- 装飾目的で数を増やさない。
- 複数アイコンの線幅、角の丸み、余白、色数を統一する。
- テキストの代替ではなく、理解を補助する要素として使う。

## 12. BOXビジュアル

### 正式スタイル

- Natural cardboard brown
- Warm Ivory tape
- Cocoa / Taupe detail
- Soft Terracotta / Warm Ivory abstract graphic
- 少しイラスト寄りのプロダクトビジュアル
- 背景透過

### 使用ルール

- SMALL / STANDARD / LARGEの見た目の縮尺差を、正式寸法・容量と矛盾しないように見せる。
- BOX Size Comparisonでは3サイズの比較が一目で分かるようにする。
- `STORAGE FOR BETTER LIVING`は正式コピーではないため、Web上のコピーとして使用しない。
- 素材上に旧コピーが残っている場合は、可能なら未確定コピーなし版を優先する。画像そのものの修正は別工程でユーザー確認後に行う。

## 13. ロゴ

- 正式採用済みの小文字`soto`ワードマークを使用する。
- Cocoa Brown系。
- シンプルで大人向け、丸すぎず親しみがある。
- 背景透過。
- キャッチコピーなしで単体利用する。
- 変形、縁取り、影、無断の色変更を行わない。
- 最小サイズ、クリアスペース、反転色の正式規定は未確定。

## 14. Responsive

### 基本方針

- モバイルファースト。
- 確認順：375 → 390 → 768 → 1024 → 1366 → 1440px。
- 確認幅ごとにmedia queryを作らず、レイアウト構造が変わる地点だけにブレークポイントを設ける。
- 768px（Tablet）と1024px（PC）は基本候補であり、実際の内容に合わせて確定する。

### SP / 375px

- 1カラム中心。
- 写真の世界観と文章理解を優先する。
- Simulatorは縦積み。
- CTAに十分なタップ領域を確保する。
- 情報を詰め込みすぎない。
- 横スクロール、コピーの不自然な改行、画像の主題切れを確認する。

### SP / 390px

- 375pxの設計を基準に、改行、余白、カード幅、CTAを確認する。
- 390px専用の調整を前提にしない。

### Tablet / 768px前後

- 内容に応じて2カラム化する。
- How It Works、Before / After、カード群の一覧性を高める。
- タッチ操作を前提とし、PC向けhoverへ依存しない。

### PC / 1024px以上

- 写真 + テキストの左右配置を使える。
- 一覧性を高めながら、横幅を広げすぎず余白を残す。
- 1366px / 1440pxでコンテナ、行長、写真のトリミング、セクション間余白を確認する。

## 15. 未確定・実装時確認

- Typographyの具体的なサイズスケール、weight、line-height、letter-spacing。
- Border Radius候補の正式採用値と用途分け。
- Spacingスケール、セクション余白、SP左右余白。
- Container最大幅。
- CTAの高さ、横幅、アイコン有無、hover候補色の正式採用。
- 写真ごとのaspect-ratioとobject-position。
- ロゴの最小サイズ、クリアスペース、反転色。
- 768px / 1024pxを正式ブレークポイントとするか。

これらは実装前または実装時の検証項目であり、本書の段階で数値を推測して固定しない。
