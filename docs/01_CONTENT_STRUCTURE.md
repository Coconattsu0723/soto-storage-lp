## 2. ユーザー心理の流れ

**共感 → 気づき → 解決理解 → 安心 → 自分ごと化 → 行動**

1. 暮らしの理想と現在の圧迫感に共感する。
2. 「捨てなくても、収納を家の外へ移せる」と気づく。
3. sotoの仕組み、預けられる物、利用手順を理解する。
4. 保管環境、料金、補償、Web管理を確認して不安を減らす。
5. Before / After、Voice、Simulatorを通じて自分の暮らしに置き換える。
6. 必要BOX数が分かった状態で申込みへ進む。

## 5. 各セクションの内容ルール

### 01 Hero

- 生活写真を主役にする。
- ブランド名、サービスカテゴリー、Hero Main Copy、Hero Sub Copy、Hero CTAを優先情報とする。
- Heroのみページの`h1`を使用する。
- 価格や細かな仕様を詰め込みすぎない。

### 02 Problem

- クローゼット、季節物、スーツケース、収納家具などの具体的な悩みを示す。
- 汚部屋やユーザーを責める表現にしない。
- 「物が多い」ではなく「使用頻度の低い物が生活空間を占めている」ことに焦点を置く。

### 03 Brand Philosophy

- 断捨離を勧めず、「大切な物を持ち続けながら暮らしの余白をつくる」という立場を示す。
- Brand Philosophy Characterを補助的に使用する。

### 04 What is soto

- 専用BOXを自宅で受け取り、荷物を詰め、集荷・保管してもらうサービスであることを簡潔に説明する。
- 大型家具・大型家電ではなく、BOXに収まる生活用品・季節用品が中心であることを明示する。

### 05 How It Works

正式な4ステップ：

1. **STEP 1 BOXを選ぶ**
2. **STEP 2 荷物を詰める**
3. **STEP 3 自宅から集荷**
4. **STEP 4 確認 / 取り出し**

詳細な申込み情報の入力や決済は、Form / 申込み導線側で補足する。

### 06 What You Can Store

正式カテゴリー：

- **SEASON**：衣類、コート、マフラー、毛布、ブランケット
- **TRAVEL**：BOXに収まるスーツケース、旅行用品
- **HOBBY**：キャンプ用品、スポーツ用品、趣味用品
- **HOME**：季節家電、インテリア小物、来客用品

預けられない物も近接して確認できるようにする。大型家具・大型家電は対象外。

### 07 Before / After Living

- BeforeとAfterはHeroと同じ住まい・同じリビング構成に見せる。
- Beforeは棚、スーツケース、季節家電、収納ケース、ブランケット等で「少し圧迫感がある状態」を表現する。
- Afterは収納ケース、季節家電、スーツケース等を減らし、床・壁際の余白を見せる。
- 大型クローゼットや不要な大型棚を追加しない。
- Afterをモデルルームのように空にしすぎない。

### 08 Storage & Security

- 24時間防犯カメラ、入退室管理、関係者以外立入禁止を伝える。
- BOXごとの管理コード、専用ラック保管、床へ直置きしないことを伝える。
- 温湿度は目安値として表示し、「常時完全一定」などの過剰表現を避ける。
- 補償は1BOXにつき最大30,000円。
- Security Icon 02はスマートフォン + BOX + チェックのシンプルな正式案を使用する。

### 09 Box / Price

- SMALL / STANDARD / LARGEの寸法、容量、月額を比較できるようにする。
- BOX代、BOX配送、初回集荷が無料であることを明示する。
- 取り出し1BOX 880円 / 回、再集荷1BOX 550円を分かりやすく併記する。
- 入会金、初期費用、最低利用期間がないことを伝える。
- LARGE BOXは最新値「W60 × D45 × H40cm / 約108L」を使用する。

### 10 Storage Simulator

- 4問の選択結果からSTANDARD BOX 1〜4箱を推奨する。
- 推奨数と月額料金（税込）を同時に表示する。
- 「BOX配送・初回集荷 0円」を補足する。
- 結果から申込みへ数量を引き継ぐ。

### 11 Why soto

既存の確定仕様から選ぶ理由を整理する。新しい機能や保証を追加しない。

候補となる訴求軸：

- 自宅から預けられる
- Webから24時間取り出し依頼ができる
- 最短翌日発送
- 1BOXから始められ、初期費用・最低利用期間がない
- BOX単位でWeb管理できる
- 保管・セキュリティ・補償の情報が明快

### 12 Voice

- 人物写真は追加しない。
- 年代、暮らし方、預けた物、コメントをテキスト中心で見せる。
- 架空の声であることを踏まえ、過度に実在体験談のように見せない方法を検討する。
- 具体的な属性とコメント本文は未確定。

### 13 FAQ

- 回答を閉じた状態でも、JavaScriptが動かない環境で内容へ到達できる設計にする。
- FAQ Characterは補助として使用し、可読性を優先する。
- 下記「FAQ候補」は質問テーマの候補であり、正式コピーではない。

### 14 Final CTA

- Final CTA Copy、補助コピー、正式CTA文言を使用する。
- Heroと同じブランド世界に見えるFinal CTA Photoを使用する。
- 強い煽り、値引き訴求、過剰な希少性表現を使わない。

### Footer

- ロゴと必要なページ内導線を配置する。
- 規約、プライバシー、事業者情報等は架空サービスとしての表示方針を確認後に確定する。

## 8. Form / 申込み導線

### 基本方針

- LPの最終CVは保管BOXの申込みに一本化する。
- Hero CTAとFinal CTAは、BOX選択または申込み開始地点へつなげる。
- Simulator結果CTAは、判定したSTANDARD BOX数を初期選択した状態で申込みエリアへつなげる。
- Formは一度に情報を詰め込みすぎず、ユーザーが現在地と次の行動を理解できる構成にする。
- 入力途中で料金、BOX種類、数量を確認できるようにする。

### 確定している申込み情報の順序

1. BOX種類・数量
2. 氏名・住所・連絡先
3. 支払い方法
4. BOX発送
5. 荷造り後、Webから集荷依頼

### 要確認事項

- FormをLP内に置くか、別画面 / モーダル / 外部申込み画面へ進めるか。
- Hero CTAの直接遷移先をBox / Priceと申込み開始のどちらにするか。
- 利用規約・プライバシーポリシーへの同意方法。
- 必須 / 任意項目、住所入力範囲、配送日時指定、確認画面の有無。
- エラー文、入力完了文、申込み完了文の正式コピー。
- Voiceの件数、属性、コメント本文。
- 主要セクションの正式な日本語見出しと英字ラベル。
- Navigation / Footerの正式リンク名。

未確定事項は実装時に推測で固定しない。
